  - เมนูแสดงลำดับที่บันทึกไว้ตลอด และ **ถ้าอยู่โหมดสีจะโชว์ "เลขสำรอง" ต่อท้ายด้วย**

    ไม่ใช่ไปเจอตอนกล้องพังกลางแข่ง — ลำดับเลขที่ผิดจะรันจนจบโดยไม่มี error อะไรเลย
    (เมนูแยกเป็น 2 บรรทัดกันล้นจอ)
  - ค่าที่เมนูแสดงคือ **ค่าในหน่วยความจำ** ไม่ใช่ค่าในไฟล์ จึงมี `unsaved_changes()` เทียบกับ
    ผลของ `load_settings()` แล้วบอกสถานะให้ชัด:
    - เมนูขึ้น `⚠️ยังไม่บันทึก` ต่อท้ายเมื่อมีอะไรในโปรแกรมที่ยังไม่ได้เขียนลงไฟล์
    - ช่องกรอกของ `[8]` เปลี่ยนวงเล็บท้ายเป็น `(Enter=Save)` เมื่อมีของค้าง / `(Enter=Exit)` เมื่อตรงกันแล้ว
    - กด Enter ตอนที่ตรงกันอยู่แล้ว จะไม่เขียนไฟล์ซ้ำ (`ℹ️ ค่าในโปรแกรมตรงกับในไฟล์อยู่แล้ว`)
    - เทียบทั้ง settings ไม่ใช่เฉพาะลำดับ `[8]` จึงเก็บของที่ค้างจาก `[7] Temp` หรือ `[2] Teach` ให้ด้วย
  - เดิมลำดับถูกจำไว้ในหน่วยความจำเท่านั้น จะลงไฟล์ก็ต่อเมื่อออกด้วย [4] Save&Exit
    ถ้าออกด้วย Enter หรือ Ctrl+C ลำดับที่เพิ่งกรอกจะหายไป
- 🐞 **ด่านตรวจ z หลุดเมื่อไม่ได้สอนจุดพัก** (อันตรายที่สุด): `measured_block_height()` ต้องใช้ทั้ง
  z ของมุมกริดและ z ของจุดพัก ถ้าไม่มีจุดพักจะคืน `None` -> `check_z_scheme()` คืน `None` ->
  ไม่มีการตรวจอะไรเลย เส้นทางที่เกิดจริง: ปิด temp ที่เมนู [7] + ยังไม่ได้สอนจุดพัก +
  เผลอสอนมุมกริดที่ "พื้น" แบบเวอร์ชันเก่า -> ผ่านทุกด่าน แล้วหัวดูดลงไปต่ำกว่าพื้น 1.62 mm
  - ตอนนี้ถ้าไม่มีจุดพัก จะถอยไปวัดเทียบกับ `ground_z` แทน (run_operation บังคับให้มีอยู่แล้ว)
  - กรณีถอยไปใช้ ground_z จะตรวจแค่ "สอนที่พื้นหรือเปล่า" ไม่เตือนเรื่อง `block_height`
    เพราะ ground_z เป็นการแตะจุดเดียว ความละเอียดไม่พอ (โต๊ะเอียงทำให้คลาดได้ 2-3 mm)
- 🐞 **กด Enter ตอน fallback หลังกล้องพังแล้วยกเลิกรันทั้งหมด**: โหมดถามเลขช่องอย่างเดียวยังใช้
  `last_input` (ซึ่งตอนนั้นเป็นชุดสี) เป็นค่าเริ่มต้น หน้าจอบอก `[g r y b] (Enter=ค่าเดิม)`
  แต่กด Enter แล้วพัง 100% -> ต้องกด [1] เริ่มใหม่ ตอนนี้โหมดนี้เสนอ `order` (ลำดับเลข) แทน

    ยืนยันจาก 3 ชุดข้อมูลอิสระ (ผิวบนบล็อก 0.6, ผิวบนบล็อก 0.5, พื้นจากจุดพัก) ทิศทางเดียวกันหมด
  - เดิมใช้ `ground_z + block_height` ค่าเดียวทั้ง 9 ช่อง -> ช่องไกลสุดหัวดูดสูงเกิน 2.4 mm (ดูดไม่ติด)
    ช่องใกล้สุดกดลงบล็อก 0.9 mm รวมช่วง 2.96 mm | ใช้ระนาบแล้วเหลือ residual 0.38 mm
  - จุดพัก: z = พื้นที่สอนไว้ (lerp ระหว่าง temp_top/temp_last) + `block_height`
    ความหมายเดียวกับของกริดคือ "ผิวบนของบล็อกที่วางตรงนั้น"
  - Tower: ชั้นที่ 1 วางที่ผิวบนของช่อง c พอดี แล้วบวกทีละ `block_height` (เดิมอิง ground_z นอกกระดาน)
  - ความสูงเดินทาง (`safe_z_for`) อ้างอิงพื้นใต้ Tower = ผิวบนช่อง c - `block_height`
- **กันพัง**: ถ้าผิวบนมุมกริดสูงกว่าพื้นน้อยกว่า 8 mm แปลว่าสอนมุมที่ "พื้น" แบบเวอร์ชันเก่า
  โปรแกรมจะไม่ยอมรัน (แขนจะกดลงโต๊ะ) และถ้า `block_height` ต่างจากที่วัดได้เกิน 2 mm จะเตือน
  ส่วนไฟล์เก่าที่ไม่มี z ในพิกัดเลย จะถอยไปใช้ `ground_z + block_height` แบบเดิม
- คำนวณ 9 ช่องแบบ affine: `ตำแหน่ง = จุดเริ่ม + คอลัมน์*u + แถว*v` จึงรองรับตารางที่วางเอียง
  - เดิมใช้ 2 มุมแล้วสมมติว่าแถว=แกน X / คอลัมน์=แกน Y ถ้าตารางเอียงจะคลาด
    (วัดจากการจำลอง: เอียง 2° คลาด 4.3 mm, 5° คลาด 10.8 mm, 10° คลาด 21.6 mm)
  - 3 มุม (ถ้ากด s ข้าม `grid_6`) = คำนวณตรงๆ ผ่านทั้งสามจุดพอดี (เอียงเท่าไหร่ก็ไม่คลาด)
  - 4 มุม = least-squares เฉลี่ยความคลาดตอนสอน (สอนคลาด σ=1 mm: 3 มุมคลาด 2.4 mm -> 4 มุม 1.6 mm)
    มุมทั้งสี่อยู่ที่ (แถว,คอลัมน์) = (0,0),(0,2),(2,0),(2,2) เป็นดีไซน์สมดุล จึงมีสูตรปิด ไม่ต้องใช้ numpy
- ค่าที่สอนไว้แบบ 2 มุมเดิมใช้ต่อไม่ได้ (ไม่ fallback เงียบๆ) โปรแกรมจะฟ้องให้กด [6] Reset แล้วสอนใหม่
- กริด 3x3 เรียงซ้าย->ขวา, บน->ล่าง = [1,2,3 / 4,c,5 / 6,7,8] โดย c คือจุดสร้าง Tower
- จุดพัก `temp_top` / `temp_last` (แตะพื้น) ยังเป็นการแบ่งเชิงเส้น 2 จุดเหมือนเดิม
- มุมหมุน r ของทุกจุดคำนวณจาก `atan2(y, x)` (ตรงกับค่าที่สอนไว้ทุกจุดในเวอร์ชันก่อน)
- ตอน [1] Run ให้เลือกลำดับบล็อก 4 ตัวจาก 8 ตัว (เช่น `3 5 8 2`) และจำค่าล่าสุดไว้ใน `order`
- สอน `grid_8` ที่พื้น จึงตั้ง Ground Z ให้อัตโนมัติ และแสดงความสูงบล็อกที่วัดได้ (ช่อง 1 - ช่อง 8)
- เมนู `[5] ShowLayout` ดูพิกัดกริดและจุดพักที่คำนวณได้ และถามต่อว่าจะให้แขนกล "เดินตรวจ" ไหม
  ถ้าตอบ y จะไล่ไปทีละจุด 1,2,3,4,c,5,6,7,8 แล้วต่อด้วย temp_1..4 (13 จุด) ลงไปที่ระดับหยิบ
  แล้วค้างจุดละ 0.5 วิ (`LAYOUT_DWELL_MS`) ใช้คำสั่ง WAIT บนหุ่น เดินระหว่างจุดที่ความสูงขาเปล่า
- คีย์พิกัดใน smart_settings.json: `grid_1`, `grid_3`, `grid_8`, `grid_6`, `temp_top`, `temp_last`
  (main_0.5 และก่อนหน้าใช้ settings.json คนละไฟล์ ไม่กระทบกัน)

### camara_2.0 — ตรวจทีละ "ช่อง" แทนทีละ "สี" (ยืดหยุ่นขึ้น)
- ปุ่ม `r` ในหน้าต่างตั้งค่า = หมุน "ผังหมายเลขช่อง" ทีละ 90° (คีย์ `rotation` 0-3 ในไฟล์ตั้งค่า)
  - หมุนแค่ตัวเลข กรอบและการตรวจสีอยู่ที่เดิม ใช้ตอนวางกล้องคนละแนวกับผังที่หุ่นใช้
  - ผังที่ได้: `rot 0` = 1 2 3 / 4 c 5 / 6 7 8, `rot 90` = 6 4 1 / 7 c 2 / 8 5 3,
    `rot 180` = 8 7 6 / 5 c 4 / 3 2 1, `rot 270` = 3 5 8 / 2 c 7 / 1 4 6 (ช่องกลางอยู่กลางเสมอ)
  - แถบล่างโชว์ `rot 90` เมื่อไม่ใช่ 0 และค่าถูกบันทึกตอนกด `k`
  - ⚠️ `rot 180` ให้ผลเท่ากับ `flip_camera` ของฝั่ง main อย่าตั้งทั้งคู่ ไม่งั้นหักล้างกัน
- ข้อความที่พิมพ์ออก terminal เป็นภาษาอังกฤษล้วนแล้ว (ไม่มีอักขระไทยเหลือในไฟล์)
  แก้เฉพาะข้อความ ตรรกะเหมือนเดิมทุกบรรทัด (เทียบ AST แล้ว)
- พลิกวิธีคิด: 1.0 ไล่ทีละสีแล้วบังคับว่าต้องเจอสีละ 2 ก้อนเป๊ะ (ไม่ครบ/เกิน = โยน error ทิ้งทั้งเฟรม)
  2.0 ไล่ทีละช่องแล้วให้แต่ละช่องสรุปสีของตัวเอง — **ทุกช่องได้สีเสมอ ไม่มี no/over color block อีก**
- **สีซ้ำกี่ก้อนก็ได้** เขียวทั้ง 8 ช่องก็ได้ ไม่จำกัดสีละ 2
- **ช่องที่มีหลายสีปนกัน -> เอาสีที่มีพิกเซลมากที่สุด** (นับพิกเซลของทุกสีในช่องแล้วเทียบกัน)
- **ระบบสำรองไล่ระดับ** (ใช้ต่อเมื่อ "หาสีไม่เจอ" จริงๆ ไม่ใช่ทางหลัก) เก็บ `reason` ไว้ในผลด้วย:
  1. `found` — เจอสีถึงเกณฑ์ตั้งแต่ range ปกติ (ปกติควรได้ทุกช่องแบบนี้)
  2. `grow` — ต้องขยาย HSV range ทีละขั้นถึงจะถึงเกณฑ์ (ยังนับว่าเจอจริง `sure=True`)
  3. `weak` — ขยายจนสุดแล้วยังไม่ถึงเกณฑ์ แต่ยังพอมีพิกเซลของสีอยู่ -> เอาสีที่มีมากที่สุด
     เท่าที่เคยเห็น (`sure=False`)
  4. `hue` — ไม่เหลือพิกเซลของสีไหนเลย -> เดาจาก H เฉลี่ยแบบวงกลมของพิกเซลที่อิ่มสีสุด 20% แรก
     แล้วหาสีที่ระยะ H ห่างน้อยสุด (`hue_gap` คิดแบบวนรอบ 180) (`sure=False`)
  - เดิมข้าม 3 ไปทำ 4 เลย ทั้งที่ยังมีหลักฐานสีอยู่ในช่อง ทำให้ทิ้งข้อมูลที่ดีกว่าไปใช้การเดาล้วน
  - `get_blocks()` แยกพิมพ์สองกรณีนี้คนละบรรทัด จะได้รู้ว่าเป็น "สีจางไป" หรือ "ไม่เห็นสีเลย"
- `cell_inset` (0.15): หดขอบช่องเข้ามาข้างละ 15% ก่อนตัดสิน กันสีช่องข้างๆ กับเส้นตารางล้นเข้ามา
- UI เหมือน 1.0 ทุกอย่าง (ปุ่ม/กรอบ/ช่องกลาง) เปลี่ยนแค่การแสดงผลในช่องกับแถบล่าง
  - ช่องที่เดา: **ชิปสีเป็นสีเทา + จุดกึ่งกลางสีเทา** แต่ **ตัวอักษรยังเป็นสีที่เดาได้** ต่อท้ายด้วย `(?)`
    เช่น `b(?)` ตัวฟ้าบนชิปเทา — แยกออกทันทีว่าอันไหนของจริงอันไหนเดา โดยยังอ่านสีได้
    (จัดตำแหน่งด้วย `getTextSize` ให้ขอบขวาชนขอบช่องพอดี ป้ายยาวไม่ล้นออกนอกช่อง)

  - **กด `m` = ทาบมาสก์ของทุกสีพร้อมกัน** ลงบนภาพจริงที่หรี่ลง 50% แต่ละสีทาด้วยสีประจำหมวดของมัน
    (เดิมกด m วนดูทีละสีเป็นภาพขาวดำ เทียบกับของจริงไม่ได้) เห็นทีเดียวว่าแต่ละช่วง HSV จับอะไรไปบ้าง

### camara_1.0 — ตรวจสีบล็อกในตาราง 3x3
- `get_blocks()` คืน `{ช่อง: สี}` ตามผัง [1,2,3 / 4,c,5 / 6,7,8] (มุมมองภาพกล้อง ช่องกลาง c ไม่นับ)
- หาให้ได้สีละ 2 ก้อน ถ้าไม่ครบจะขยาย HSV range ทีละขั้น (h ±3, s/v -15 ต่อขั้น) จนถึง `expand_limit`
  - ไม่ครบหลังขยายสุด -> `no color block: <สี>`
  - เจอเกิน 2 ก้อน -> `over color block: <สี>`
  - ก้อนที่อยู่นอกกรอบ 3x3 -> ตัดทิ้งไม่นับ
- 🐞 UI ตั้งกรอบเคยไม่โชว์อะไรเลยถ้ายังหาสีไม่ครบสีละ 2 ก้อน (เห็นสีเขียวชัดๆ แต่ช่องไม่ขึ้น `g`)
  เพราะเรียก `detect()` ตัวเดียวกับของจริง ซึ่งโยน CameraError ทันทีที่สีแรกไม่ครบ -> `blocks = {}`
  แยกเป็น `scan_color()` + `preview()` แบบหลวมสำหรับ UI: เจอกี่ก้อนก็โชว์เท่านั้น
  แถบล่างบอกจำนวนที่เจอรายสี (`found g=1 r=0 y=2 b=2 (need 2 each)` / `READY g=2 r=2 y=2 b=2`)
  และ `min_area` ปัจจุบัน ส่วนก้อนที่ตกนอกกรอบวาดเป็นกากบาทเอียง + `g out` จะได้รู้ว่าเห็นแต่กรอบไม่ครอบ
  (`detect()` / `get_blocks()` ยังเข้มงวดเหมือนเดิม ไม่เปลี่ยนพฤติกรรมตอนแข่ง)
- UI ตั้งกรอบ (รัน `python3 camara_1.0.py`): วาดตาราง 3x3 ทับภาพสด
  `w/a/s/d` เลื่อนกรอบ, `+/-` ซูมกรอบ, `[ / ]` ปรับ min_area, `m` ดูมาสก์รายสี, `k` บันทึก, `q` ออก
  แถบล่างโชว์ผลตรวจสดๆ หรือข้อความ error ทำให้จัดกรอบแล้วเห็นผลทันที
- **ไม่มีกล้องเสริมก็ใช้กล้องโน้ตบุ๊กแทนอัตโนมัติ**: `open_camera()` ไล่เปิดตามลำดับ
  `camera_index` ที่ตั้งไว้ -> กล้องอื่นใน `/dev/v4l/by-id/` -> index 0-3 แล้วเลือกตัวแรกที่
  **เปิดติดและอ่านภาพออกจริง** (แค่ `isOpened()` ไม่พอ บาง /dev/video เป็น node ที่เปิดได้แต่อ่านไม่ได้)
  - พิมพ์ `📷 ใช้กล้อง: ...` ทุกครั้ง และเตือนถ้าไม่ใช่ตัวที่ตั้งไว้ จะได้รู้ว่ากำลังใช้กล้องไหน
  - ตัวที่ชี้ตัวเดียวกัน (path vs index) ถูกตัดซ้ำด้วย `os.path.realpath`
  - ตอนไล่เปิด ปิด log ของ OpenCV ชั่วคราว ไม่ให้ warning ท่วมจอ
  - UI ตั้งกรอบเตือนด้วย ว่ากรอบที่จัดจะตรงกับกล้องตัวที่ใช้อยู่เท่านั้น (มุมมองกล้องคนละตัวไม่เท่ากัน)
- **ขนาดวัตถุต่ำสุดผูกกับขนาดกรอบ**: เปลี่ยนจาก `min_area` (พิกเซลตายตัว) เป็น
  `min_area_ratio` = สัดส่วนของพื้นที่ 1 ช่อง (ค่าเริ่มต้น 0.04 = 4%) แล้วคำนวณพิกเซลจริงด้วย
  `min_area_of(cfg)` = ratio x (กว้างกรอบ/3) x (สูงกรอบ/3)
  - ซูมกรอบเข้า/ออก หรือย้ายไปใช้กล้องที่ความละเอียดต่างกัน เกณฑ์ก็ขยับตามเอง ไม่ต้องจูนใหม่
    (กรอบ 300 -> 400 px, กรอบ 600 -> 1600 px, กรอบ 150 -> 100 px)
  - ปุ่ม `[` / `]` ปรับเป็นเปอร์เซ็นต์ (±0.5% ต่อครั้ง, ช่วง 0.2%-50%) แถบล่างโชว์ทั้งสองแบบ
    `min_area=400px (4.0% of cell)`
  - ไฟล์เก่าที่เก็บ `min_area` เป็นพิกเซล จะถูกแปลงเป็น ratio ให้เองตอนโหลด โดยเทียบกับกรอบที่เซฟไว้
- ค่าตั้งเก็บใน `camera_config.json` (camera_index, กรอบ cx/cy/w/h, min_area_ratio, expand_limit, ช่วง HSV)
