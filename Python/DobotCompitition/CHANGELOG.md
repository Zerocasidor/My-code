### main_0.6 — สอนมุมกริด 3-4 มุม แล้วคำนวณ 9 ช่องเอง
- `keep_rotation` (ค่าเริ่มต้น true) และเมนู `[6] ResetPositions` แบบเดียวกับ main_0.5
  (คงมุม r ตอนหยิบไว้จนวางเสร็จ / ล้างพิกัดที่สอนไว้ทั้งหมดเพื่อเริ่มสอนใหม่)
- กติกา temp เปลี่ยนอีกครั้ง: **ลำดับที่ 3 และ 4 ต้องพักที่ temp เสมอ** ไม่ว่าจะเป็นช่องไหน
  (Tower สูง 2-3 ชั้นแล้ว เสี่ยงชนตอนเอื้อมข้าม) ส่วนลำดับ 1-2 ไม่ต้องพัก
- เมนู `[7] Temp:ON/OFF` เปิด/ปิดการใช้จุดพักได้ (คีย์ `use_temp` ในไฟล์ตั้งค่า) ปิดแล้วทุกลำดับ
  หยิบจากช่องเดิมไปวาง Tower ตรงๆ และไม่ต้องสอน temp_top/temp_last ก็รันได้ สถานะโชว์ในเมนู
- สอนมุมกริด **4 มุม** `grid_1` (บนซ้าย), `grid_3` (บนขวา), `grid_8` (ล่างขวา), `grid_6` (ล่างซ้าย)
  ทุกมุมสอนที่ **"ผิวบนของบล็อก" เหมือนกันหมด** (วางบล็อกไว้ 4 มุมก่อนสอน) ไม่ต้องสลับไปแตะพื้น
- **ระดับพื้น (ground_z) มาจากจุดพัก**: เฉลี่ย z ของ `temp_top` กับ `temp_last` ซึ่งเป็นพื้นที่ว่าง
  แตะพื้นได้จริง (เดิมใช้ z ของ `grid_8`) แล้วพิมพ์ความสูงบล็อกที่วัดได้ = ผิวบนเฉลี่ย 4 มุม - พื้น
  เทียบกับค่า `block_height` ที่ใช้อยู่ให้ดู
- คำนวณ 9 ช่องแบบ affine: `ตำแหน่ง = จุดเริ่ม + คอลัมน์*u + แถว*v` จึงรองรับตารางที่วางเอียง
  - เดิมใช้ 2 มุมแล้วสมมติว่าแถว=แกน X / คอลัมน์=แกน Y ถ้าตารางเอียงจะคลาด
    (วัดจากการจำลอง: เอียง 2° คลาด 4.3 mm, 5° คลาด 10.8 mm, 10° คลาด 21.6 mm)
  - 3 มุม (ถ้ากด s ข้าม `grid_6`) = คำนวณตรงๆ ผ่านทั้งสามจุดพอดี (เอียงเท่าไหร่ก็ไม่คลาด)
  - 4 มุม = least-squares เฉลี่ยความคลาดตอนสอน (สอนคลาด σ=1 mm: 3 มุมคลาด 2.4 mm -> 4 มุม 1.6 mm)
    มุมทั้งสี่อยู่ที่ (แถว,คอลัมน์) = (0,0),(0,2),(2,0),(2,2) เป็นดีไซน์สมดุล จึงมีสูตรปิด ไม่ต้องใช้ numpy
- ค่าที่สอนไว้แบบ 2 มุมเดิมใช้ต่อไม่ได้ (ไม่ fallback เงียบๆ) โปรแกรมจะฟ้องให้กด [6] Reset แล้วสอนใหม่
- กริด 3x3 เรียงซ้าย->ขวา, บน->ล่าง = [1,2,3 / 4,c,5 / 6,7,8] โดย c คือจุดสร้าง Tower
- จุดพัก `temp_top` / `temp_last` (แตะพื้น) ยังเป็นการแบ่งเชิงเส้น 2 จุดเหมือนเดิม
- มุมหมุน r ของทุกจุดคำนวณจาก `atan2(y, x)` (ตรงกับค่าที่สอนไว้ทุกจุดในเวอร์ชันก่อน)
- ตอน [1] Run ให้เลือกลำดับบล็อก 4 ตัวจาก 8 ตัว (เช่น `3 5 8 2`) และจำค่าล่าสุดไว้ใน `order`
- สอน `grid_8` ที่พื้น จึงตั้ง Ground Z ให้อัตโนมัติ และแสดงความสูงบล็อกที่วัดได้ (ช่อง 1 - ช่อง 8)
- เมนู `[5] ShowLayout` ดูพิกัดกริดและจุดพักที่คำนวณได้ และถามต่อว่าจะให้แขนกล "เดินตรวจ" ไหม
  ถ้าตอบ y จะไล่ไปทีละจุด 1,2,3,4,c,5,6,7,8 แล้วต่อด้วย temp_1..4 (13 จุด) ลงไปที่ระดับหยิบ
  แล้วค้างจุดละ 0.5 วิ (`LAYOUT_DWELL_MS`) ใช้คำสั่ง WAIT บนหุ่น เดินระหว่างจุดที่ความสูงขาเปล่า
- คีย์พิกัดใน smart_settings.json: `grid_1`, `grid_3`, `grid_8`, `grid_6`, `temp_top`, `temp_last`
  (main_0.5 และก่อนหน้าใช้ settings.json คนละไฟล์ ไม่กระทบกัน)

### main_0.5 — ขาเปล่าบินต่ำลง 1 บล็อก
- `keep_rotation` (ค่าเริ่มต้น true): คงมุม r ตอนหยิบไว้ตลอดขาที่ถือบล็อก แล้ววางด้วยมุมเดียวกัน
  เดิมวางด้วย r ของจุดปลายทาง บล็อกจึงถูกหมุนไปเท่ากับมุมที่แขนกวาดไป (วัดจากพิกัดที่สอนไว้ = -9.4° ถึง +9.2°)
  ตั้งเป็น false ได้ถ้าอยากได้พฤติกรรมเดิม
- เมนู `[5] ResetPositions`: ล้างพิกัดที่สอนไว้ทั้งหมด (pick_1..4, temp_1..4, center) เพื่อเริ่มสอนใหม่
  แก้ปัญหา temp เก่าค้างจากรอบก่อน — ถามยืนยัน y/n ก่อน และต้องกด [4] Save&Exit เพื่อเขียนลงไฟล์
  (ไม่แตะ ground_z / ความเร็ว / ความสูงบล็อก)
- แยกความสูงเดินทางเป็น 2 แบบ: ขาที่ถือบล็อก (carry) กับขาตัวเปล่า (empty)
  - ถือบล็อก: 2.5x / 3.5x / 4.5x ของความสูงบล็อก (เท่าเดิม — เผื่อใต้บล็อกที่ถือ 0.5 บล็อก)
  - ตัวเปล่า: 1.5x บนโต๊ะ และ (ความสูง Tower + 0.5) เมื่อออกจาก Tower
- สูตรรวมอยู่ใน `safe_z_for(..., carrying=True/False)` = (สิ่งกีดขวางสูงสุด + 1.5 หรือ 0.5) x ความสูงบล็อก
- ถ้าหน่วงหัวดูด = 0 ms จะไม่ส่งคำสั่ง WAIT เข้าคิวเลย (คิวเหลือ 56 คำสั่งต่อรอบ)
- ⚠️ ขาเปล่าเหนือ Tower เหลือระยะห่างแค่ 0.5 บล็อก (12.5 mm) และการเคลื่อนที่แนวราบเป็นแบบ MOVJ
  ซึ่ง Z อาจแกว่งลงระหว่างทาง — ถ้าเฉี่ยว ให้เพิ่มเลข 0.5 ใน `safe_z_for()`

### main_0.41 — ทดลอง JUMP (ช้ากว่า เลิกใช้)
- ใช้คำสั่ง JUMP_XYZ (ยก-เคลื่อน-ลง ในคำสั่งเดียว) แทนการสั่งทีละท่อน
- ตั้ง `jumpHeight = safe_z - z ปัจจุบัน` และ `zLimit = safe_z` ให้ความสูงเดินทางเท่าเดิม

### main_0.4 — เวอร์ชัน lightweight + ส่งทั้งชุดเข้าคิว
- ลดเหลือ 5 เมนู: `[1]Run [2]Teach&Save [3]SetGround [4]Save&Exit [Enter]Exit` (221 บรรทัด จาก 622)

- ส่งคำสั่งทั้งชุดของแต่ละบล็อกเข้าคิวของหุ่นยนต์ทีเดียว แล้วรอแค่บล็อกก่อนหน้า
  (คิวไม่เกิน 2 บล็อก ~22 คำสั่ง < 32) — ไม่มีช่วงรอฝั่ง Python ระหว่างแต่ละท่อน
- หน่วงหัวดูดใช้คำสั่ง WAIT (ID 110) ที่รันบนหุ่นยนต์ แทน `time.sleep()` — ตั้งที่
  `SUCK_DELAY_MS` / `RELEASE_DELAY_MS` (ปัจจุบันตั้ง 0 ms ทั้งคู่ ทดสอบแล้วบล็อกไม่หลุด)
- ตัดการยกขึ้นหลังวางบล็อก — การยกครั้งถัดไปยกตรงไปที่ Safe Z ของบล็อกถัดไปครั้งเดียว
- ตัด `time.sleep(0.1)` หลังทุกการเคลื่อนที่ (ไม่มีผล เพราะรอคำสั่งเสร็จอยู่แล้ว) ~5.8 วินาที/รอบ
- ถาม `get_pose()` ครั้งเดียวตอนเริ่มรัน (เดิมถามทุกบล็อก) โดยจำตำแหน่งล่าสุดไว้เอง
- Ctrl+C / ออกจากโปรแกรม: สั่งหยุดฉุกเฉิน (ID 242) + ล้างคิว (ID 245) + ปิดหัวดูด
  เดิม Ctrl+C หยุดแค่ Python ส่วนหุ่นยนต์ยังวิ่งคำสั่งที่ค้างในคิวต่อ
- แสดงเวลาที่ใช้ต่อรอบเป็นวินาที ท้ายข้อความ "สร้าง Tower เสร็จ"

### camara_1.0 — ตรวจสีบล็อกในตาราง 3x3
- `get_blocks()` คืน `{ช่อง: สี}` ตามผัง [1,2,3 / 4,c,5 / 6,7,8] (มุมมองภาพกล้อง ช่องกลาง c ไม่นับ)
- หาให้ได้สีละ 2 ก้อน ถ้าไม่ครบจะขยาย HSV range ทีละขั้น (h ±3, s/v -15 ต่อขั้น) จนถึง `expand_limit`
  - ไม่ครบหลังขยายสุด -> `no color block: <สี>`
  - เจอเกิน 2 ก้อน -> `over color block: <สี>`
  - ก้อนที่อยู่นอกกรอบ 3x3 -> ตัดทิ้งไม่นับ
- UI ตั้งกรอบ (รัน `python3 camara_1.0.py`): วาดตาราง 3x3 ทับภาพสด
  `w/a/s/d` เลื่อนกรอบ, `+/-` ซูมกรอบ, `[ / ]` ปรับ min_area, `m` ดูมาสก์รายสี, `k` บันทึก, `q` ออก
  แถบล่างโชว์ผลตรวจสดๆ หรือข้อความ error ทำให้จัดกรอบแล้วเห็นผลทันที
